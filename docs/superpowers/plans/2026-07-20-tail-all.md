# Tail All Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Status:** Implemented 2026-07-20 in the same PR that introduced this file. Tasks
1-4 are done and verified by `tsc` on both projects plus the full Vitest suite;
the manual in-app checks at the bottom are left unticked because they require a
running app and a human looking at it.

**Goal:** One palette toggle that puts *every currently visible agent pane* into
tail (feed auto-follow), and takes them all back out. It is a **stance on the
workspace**, not a batch operation: panes that become visible later — a new lane
selection, a tab switch, a fresh split — are tailing too, without the user
re-running anything.

**Architecture:** A single boolean on the UI-shell store, OR-ed into the existing
per-session `tailMode` at the two points where `TileLeaf` already hands tail down
to `Feed`. There is deliberately **no** enumeration of visible sessions — see
"Why there is no visible-session selector" below, which is the whole reason this
plan is small.

**Tech Stack:** TypeScript, React, Zustand (`app-state/uiShell`), existing
command registry.

---

## Background: what exists today

Tail is one field on the per-session runtime:

- `tailMode: boolean` — `src/renderer/src/session-runtime/state.ts:431`, default
  `false` at `:686`. No slice, no persistence, keyed by **sessionId**.
- It survives a soft session reset on purpose —
  `src/renderer/src/workspace/hook/actions/session.ts:158` carries it across and
  calls it "the tail preference".
- The only mutator is a toggle: `toggleTailMode(sessionId)` at
  `src/renderer/src/workspace/hook/helpers.ts:94-108`. There is **no**
  `setTailMode(sessionId, on)`.
- One command drives it: `toggle-tail`,
  `src/renderer/src/features/workspace/commands/paneCommands.ts:376-407`,
  `surface: 'session'`, targeting `commandTargetSessionId(workspace)`. No
  keybinding — `grep toggle-tail` returns exactly one hit.
- It is agent-only. The command's `when` guard excludes `kind === 'terminal'`
  with a recorded WHY: terminal panes delegate scrollback to xterm.js, so the
  flag would present a command that appears to work while changing nothing.
- The only visual is a non-clickable `TAIL` pill —
  `src/renderer/src/workspace/tile-tree/TileLeaf/ScrollIndicator.tsx:90`.

`tailMode` reaches the renderer through exactly **two** props, both in
`src/renderer/src/workspace/tile-tree/TileLeaf.tsx`:

- `:568` → `Feed` (the behavior)
- `:658` → `ScrollIndicator` (the pill)

`Feed` consumes it at `features/feed/ui/Feed.tsx:409, 452, 488, 547, 574` — mount
pin, scroll-listener re-pin, older-history lazy-load suppression, append
auto-scroll, bootstrap→live pin-once.

## Why there is no visible-session selector

The obvious design — "enumerate the visible panes, write `tailMode` on each" —
is the wrong shape here, and it is worth recording why, because it looks like the
natural reading of the feature request.

There is **no canonical visible-session selector in this codebase.** Nothing named
`selectVisibleSessionIds` exists. `resolveTabSessions` (`workspace/queries.ts:59-85`)
answers *membership*, not visibility, and its own header says so at `:26-32`.
Visibility is instead re-derived independently by `MainSurface`, `DispatchLayout`,
`TiledDispatchLayout`, `TileTabsView`, `SpotlightView`, `agentIndexNavigation.ts`,
`paneLabels.ts`, and `useKeybinds.ts`. Writing a ninth derivation would mean
hand-encoding all of:

- the `MainSurface.tsx:75-130` mode ladder, including that `tileTabs` /
  `spotlight` / `readerMode` live in a *different store* than `dispatchMode` and
  rehydrate independently — two modes can be non-null at once, which is why two
  files already carry hand-written `!tileTabs` precedence guards;
- Tiled Dispatch permitting **duplicate lanes** on one session (dedupe needed);
- a grid leaf rendering a *related detached child* rather than its own session
  via `gridRelatedSelections` (`TileTree.tsx:110-113`), so the session to tail is
  the **rendered** one, not the leaf owner;
- terminal panes, in both flavors (`TerminalLeaf` and an agent in
  native-terminal surface mode).

Every one of those is a way to get the set subtly wrong, and each would need
re-checking whenever a layout mode changes.

**The shortcut:** `TileLeaf` *is* the visibility predicate. It mounts if and only
if a pane is on screen. So OR-ing a global flag into the tail prop at those two
existing sites yields the requested scoping as a consequence of what React
already mounts:

| Mode | Falls out as |
|---|---|
| Classic Dispatch ("single dispatch") | the one mounted agent pane |
| Tiled Dispatch ("tiled") | every mounted lane; duplicate lanes mirror correctly, for free |
| Grid | every leaf of the **active tab** only — unmounted tabs render nothing, so tab-scoping is automatic |
| Tiled Tabs / Spotlight / Reader | whatever is mounted, with no extra code |
| Terminals | never tail — they don't render `Feed` at all |

That last column is the point: modes nobody thought about are handled, and a
future mode is handled before it is written.

## Design decisions

**D1 — Effective tail is `runtime.tailMode || tailAllMode`.** A plain OR, resolved
at the consumer. Tail All never writes per-session state, so it needs no
reconciliation, no snapshot of prior values, and no restore-on-off: switching it
off simply reveals the per-session flags that were there all along. The
alternative (bulk-writing every session's `tailMode`) would need a
`setTailMode(sessionId, on)` primitive that does not exist, plus a memory of what
each session was before, plus a policy for sessions created while it was on.

**D2 — Not persisted.** Per-session `tailMode` is not persisted either
(`state.ts:686` defaults it `false` and nothing in `workspace/hook/persistence/*`
writes it). A stance that silently survives a restart and pins every feed to the
bottom is a confusing thing to wake up to. Restarting clears it.

**D3 — `surface: 'app'`, not `'session'`.** It acts on the workspace, not on the
command target. This follows the recorded precedent for
`switch-agents-provider` (`sessionCommands.ts:222-232`): app-surface because
"the user is acting on a batch across the workspace, not on the focused pane".

**D4 — No keybinding.** Matches `toggle-tail`, which has none. Palette only.

**D5 — Per-session `toggle-tail` keeps working and is not disabled while Tail All
is on.** It still flips its own flag; the flag is simply masked until Tail All
goes off. Its `getState` label surfaces that so the command does not look broken.

## What this plan explicitly does NOT do

- No `setTailMode` primitive. Nothing bulk-writes runtime state.
- No visible-session enumeration, in any mode.
- No new tests. (Repo convention for feature PRs; the OR is one expression and
  the rest is store boilerplate.)
- No clickable `TAIL` pill. The indicator stays read-only, as it is today.
- No persistence, no settings entry, no per-project scoping.

- [x] `getState: ({ ui }) => ({ label: ui.tailAllMode ? 'On' : 'Off', tone: ui.tailAllMode ? 'accent' : 'neutral' })`

      check on one resolved session; Tail All has no single target. Add a comment

- [x] Write the `description` in the established three-part palette format
      (**What it does** / **Use when** / **Notes**). The Notes line must state the
      scoping rule in user terms: single dispatch is the one visible agent, tiled
      is every lane, grid is the current tab's panes, and terminals are never
      affected.

**Verify:** confirm the command context actually exposes `ui` with store fields —
check the `ui` type in `features/command-palette/types.ts` and how
`sessionCommands.ts` consumes `ui`. If `ui` does not surface store state to

inventing one.
